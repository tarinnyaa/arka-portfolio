# ARKA — interactive research portfolio

A public, interactive portfolio for **ARKA**, a research platform for light-based
behavioural interventions built at the Eye N' Brain lab, NUS Yong Loo Lin School
of Medicine. It is an exhibition of one sensing-and-intervention platform adapting
to five populations — not a product landing page.

Routes: `/` (About) · `/healthy` · `/myopia` · `/glaucoma` · `/depression` · `/stroke`

## Run

```sh
npm install
npm run dev        # http://localhost:5173
npm run build      # tsc --noEmit, vite build, copies index.html → 404.html
npm run preview    # serve the production build
npm run typecheck
```

Stack: Vite + TypeScript, no UI framework. GSAP (ScrollTrigger) drives the
scroll-scrubbed scenes. Fonts load from Google Fonts via `<link>` in
`index.html`. Every phone screen, chart, diagram and mockup is real HTML/SVG;
the only raster images are the supplied photographs and illustrations.

## Deploy

`.github/workflows/deploy.yml` builds on every push to `main` and publishes
`dist/` to GitHub Pages (Actions → Pages, "GitHub Actions" source). Vite's
`base` is set to `/arka-portfolio/` for production builds in `vite.config.ts`;
`404.html` is a copy of `index.html` so deep links resolve under the SPA router.

## Where things live

| Path | What |
| --- | --- |
| `content/*.ts` | **All copy, citations and references.** One file per page plus `shared.ts`, `references.ts` (light-health targets) and `design-references.ts` (interface/accessibility references). Editable without touching components. |
| `src/pages/` | One module per route, lazy-loaded by the router. |
| `src/scenes/` | Scroll-driven and interactive scenes (About page scenes, plant, garden, unlock, seed-follow). |
| `src/components/` | Shared UI: chrome, frames, callouts, evidence markers, plant renderer, phone screens, config cards, drawers. |
| `src/styles/` | `tokens.css` (design tokens), `base.css`, `components.css`, `screens.css`, `pages.css`. |
| `src/lib/` | Router, motion helpers (reduced-motion aware), Explore/Research mode, circadian ambient, DOM builder. |
| `public/assets/` | `brand/`, `illustrations/`, `flowers/`, `screenshots/`. |
| `scripts/` | One-off asset extraction (documented in the script header). |

### Content rules

Three categories of claim are kept distinct in `content/`:

1. **Light-health intervention targets** — cited only to the references in
   `content/references.ts` (from the lab's vetted deck).
2. **Interface and accessibility principles** — cited only to entries in
   `content/design-references.ts` marked `verified: true`.
3. **ARKA design hypotheses** — untested; worded as *designed to*, *proposed*,
   *informed by*. Only the Myopia page describes functionality as deployed.

Every chart sits inside `ChartFrame` and is labelled *Illustrative data*.
Citations appear as superscripts only in **Research** mode (top-bar toggle).

## Assets and where they came from

- `public/assets/illustrations/*.png` and `brand/hero-ecosystem.png` — supplied
  by the author. `hero-ecosystem.png` was moved from `illustrations/` to `brand/`.
  The site references the `.webp` versions next to them, produced by
  `scripts/optimize-images.sh` (needs `cwebp`); the originals are kept.
- `public/assets/brand/logo.svg` — the ARKA mark, supplied by the author.
  `public/favicon.svg` is derived from it.
- `public/assets/screenshots/*.png` — screenshots of the deployed Myopia app,
  copied from the author's `arka-screenshots` folder; used as reference for the
  Myopia mockups.
- `public/assets/flowers/*.svg` and `src/lib/flowerArt.*.gen.ts` — generated by
  `scripts/extract-flower-art.ts`, which reads the deployed app's traced path
  data read-only and emits standalone SVGs plus two site-local modules
  (`npm run assets:flowers`). Nothing in `src/` references the app repo.
- **Missing** (rendered as labelled placeholders sized like the real assets):
  `brand/actlumus.png`, `brand/eye-n-brain.png`, `brand/nus-medicine.png`,
  `brand/og-image.png`. Drop the files in and the layout needs no change.

## Accessibility

Targets WCAG 2.2 AA: 4.5:1 text contrast (including on the circadian ambient
and aperture tints), keyboard operability with visible focus, semantic
landmarks, text summaries for every chart, 44×44 targets, and full
`prefers-reduced-motion` support — every scrubbed scene renders its end state
with a segmented control to step through states manually, and the route wipe
is disabled.
